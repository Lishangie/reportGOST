# Отчёты для вуза: инструкция для ИИ-агента

Эта папка — система подготовки учебных работ (практические, курсовые, отчёты
по практике) по нормоконтролю кафедры ПМ РТУ МИРЭА. Ты пишешь `report.md`,
документ Word из него собирает `build.py`.

## Файлы

| Файл | Зачем |
| --- | --- |
| `build.py`, `template.docx` | сборщик: `report.md` → `.docx` (+ PDF). Оформление делает он, его не настраивают под работу |
| `Собрать.bat` | запуск сборки двойным щелчком или перетаскиванием `report.md`; сам ставит библиотеки |
| `ФОРМАТ.md` | синтаксис `report.md` — **прочитай перед первым отчётом** |
| `НОРМОКОНТРОЛЬ.md` | требования нормоконтроля: что делает скрипт, что обязан соблюсти автор |
| `Кафедры.md` | профили предметов: состав работы, блок `[настройки]`, требования преподавателей (если файла нет — скопировать `Кафедры.пример.md`) |
| `примеры/` | два эталонных отчёта (курсовая и практическая) со всеми элементами |
| `Проверка.bat`, `check.py` | пересобирают примеры в Word; после правок сборщика должно быть «Всё чисто» |
| `_материалы/` | исходник нормоконтроля (слайды вебинара 2026), если нужно свериться |

## Роль и результат

Твой результат — файл `report.md` в папке работы (и PNG графиков в `img/`, код
в `code/`), а не .docx. Оформление (шрифты, интервалы, поля, подписи, нумерация,
ссылки-поля, оглавление, «Продолжение таблицы», пустые места) делает `build.py`.
**Твоя зона — структура и содержание** и правила текста ниже: их скрипт
проверяет только частично.

Новая работа: `python build.py --init "путь\к\папке работы"` — создаст
`report.md`, `img/`, `code/` и `Собрать.bat`, который вызывает сборщик из этой
папки (копировать `build.py` в папку работы не нужно). Одна папка — одна работа.

Сборка: `python build.py "путь\к\report.md" --pdf`. Документ для сдачи
собирается на Windows с установленным Word: вёрстка проверяется именно в нём
(LibreOffice — запасной вариант, страницы он разбивает иначе). Если можешь
запускать команды — собирай сам и читай вывод; если нет — пользователь запускает
`Собрать.bat` и присылает вывод текстом.

## Структура решается под предмет

Состав работы у каждого предмета свой. Не подставляй типовую структуру курсовой
и ничего сверх профиля не добавляй.

1. Найди предмет в `Кафедры.md` — бери состав и блок `[настройки]` дословно.
2. Если предмета нет — выведи требования из методички или задания: состав,
   титул, содержание, список источников и сколько, нумерация, объём.
3. Чего в материалах нет — спроси одним списком, предложив типовой вариант.
4. Переведи это в `[настройки]` (+ `обязательно = …`) и набор заголовков.
   Ненужных разделов просто нет в файле. Титул пользователь вставляет сам.
5. Для нового предмета допиши короткий профиль в `Кафедры.md` (5–10 строк).

## Правила текста

**Объекты.** Каждый рисунок, таблица, листинг, приложение упоминается в абзаце
прямо перед ним, полным словом с прописной: «на Рисунке {рис:id}», «в Таблице
{табл:id}», «в Листинге {лист:id}», «в Приложении {прил:А}», «по формуле
{форм:id}». Без «ниже», «выше», «рис.», «табл.». После каждого объекта — хотя бы
одно предложение (вывод по нему); два объекта подряд и раздел, кончающийся
рисунком, таблицей или списком, — нельзя. Подписи — с прописной, без точки,
по смыслу, без слова «Рисунок». Внутри списка объектов нет.

**Абзацы вокруг рисунков.** Вывод по рисунку и фразу, вводящую следующий
рисунок, пиши **разными абзацами**: вёрстка заполняет пустое место, перенося
вывод перед рисунком, а вводный абзац трогать не может. После крупного рисунка
давай два-три коротких абзаца, а не один длинный.

**Формулы.** Всё математическое — формулами: в строке `$…$`, отдельно
`[формула:]`. В обычном тексте знаков «=», «<», «+» без чисел нет («меньше»,
«равно»). Номер — только у формул со ссылкой. Под формулой «где» и каждое
обозначение в порядке появления, если оно не пояснено раньше.

**Числа.** Десятичная запятая (в LaTeX `0{,}05`). Числа без единиц от одного
до девяти — словами («три файла»), с единицами — цифрами («5 см»). Единица —
после последнего значения ряда или диапазона: «от 5 до 10 мм», «100-150 Мб».
Числительные без падежных окончаний («в 5 файлах», не «5-ти»). Века, кварталы,
полугодия — римскими цифрами.

**Списки.** Маркированный пункт — со строчной, одна мысль одним предложением,
«;», последний «.». Нумерованный — с прописной, с точкой. После списка —
поясняющее предложение, если дальше заголовок.

**Таблицы.** Единицы — в шапке или в названии, не в ячейках. Графы «№ п/п» нет.
Пустая ячейка — «—». Шапка с прописной, без точек. До пяти граф, в первой
графе короткие названия.

**Заголовки.** Кратко, по смыслу, без сокращений и точки. Делишь раздел — хотя
бы два подраздела. Не глубже трёх уровней.

**Источники.** Только реальные, проверенные поиском, иначе честно «нужен
подбор». ГОСТ Р 7.0.5: «Автор И. О. Название. — Город: Изд-во, год. — N с.»;
электронные — «— URL: … (дата обращения: ДД.ММ.ГГГГ).» Ссылка до точки:
«… [1].» Во введении и заключении ссылок нет. Для курсовой по умолчанию 5–7,
не старше 5 лет.

**Графики** (если строишь сам): 200 dpi, белый фон, без заголовка внутри
(название — в подписи), подписи осей по-русски, десятичная запятая на осях,
шрифт читаем при ширине 15 см, `bbox_inches="tight"`.

**Страницы.** Альбомные — только для рисунков и таблиц. Совсем короткий раздел
перед новой страницей даёт полупустой лист (больше 50 % пусто — замечание):
лучше дописать вывод, чем оставить два предложения.

Цифры и результаты — только из данных пользователя или из твоих расчётов.

## Порядок работы

1. **Приём.** Профиль предмета и план: разделы, рисунки и таблицы с номерами
   и именами файлов (`img/рис_1_1.png`). Дождись «ок».
2. **Практическая часть.** Если её делает пользователь — один рабочий лист:
   действия по пунктам, что под каким именем сохранить, в конце форма возврата
   (что принести текстом). Если делаешь сам — расчёты, графики, код.
3. **Текст.** `report.md` целиком.
4. **Сборка.** Вывод сборщика: «Исправлено автоматически» — справочно.
   «ЗАМЕЧАНИЯ НОРМОКОНТРОЛЯ» — на каждое исправь строку `report.md` (номер
   строки указан). «ВЁРСТКА» — пустое место: допиши 1–2 предложения перед
   объектом на указанной странице или в конец раздела, либо уменьши рисунок
   (4-е поле `[рис: …| 12]`). Повторяй, пока не будет «Замечаний нет».
5. **Правки.** Меняй только нужные фрагменты, остальное не трогай.

Экономь контекст: скриншоты не читай без необходимости (имена файлов рисунков
назначаются в плане, пользователь кладёт их в `img/`); цифры, вывод программ
и ошибки — только текстом; без вступлений и пересказов.

## Чего не делать

- Не править `build.py` и `template.docx` ради одной работы. Ошибка сборщика —
  отдельная задача: воспроизведи на `примеры/`, исправь, запусти `Проверка.bat`
  (Word, оба примера без замечаний), обнови номер версии в `build.py` и `ФОРМАТ.md`.
- Не обходить замечания сборщика (не убирать `обязательно`, не отключать
  вёрстку), а исправлять текст.
- Не редактировать готовый .docx руками: правки вносятся в `report.md`,
  документ пересобирается. Исключение — титульный лист.
